Docker and Kubernetes

The image is built for Fly.io, but nothing in it requires Fly.io. It runs anywhere a container can mount a FUSE filesystem, with any S3-compatible bucket (AWS S3, Cloudflare R2, MinIO, Tigris and others).

Requirements

Section titled “Requirements”
  • FUSE. GeeseFS mounts the bucket at /mnt/s3. The container needs the /dev/fuse device and the SYS_ADMIN capability. Some hosts also need AppArmor relaxed for the container.
  • Exactly one replica. Litestream must be the only writer of the replica. Never run two containers against the same bucket at the same time, not even briefly during an update.
  • No persistent volume. State lives in the bucket. The container filesystem may be thrown away at any time.
  • VAULTWARDEN_DOMAIN. On Fly.io it defaults to https://<app>.fly.dev. Elsewhere, always set it.

All other options are the same as on Fly.io. See the configuration reference. Vaultwarden listens on port 8080.

Docker

Section titled “Docker”

VAULTWARDEN_RSA_PRIVATE_KEY spans several lines, which an env file can’t hold. Pass it with -e VAULTWARDEN_RSA_PRIVATE_KEY="$(cat rsa_key.pem)".

Put a reverse proxy that terminates TLS in front of port 8080. Set VAULTWARDEN_IP_HEADER to the header your proxy sets, for example X-Forwarded-For.

Kubernetes

Section titled “Kubernetes”

A Deployment with one replica and the Recreate strategy makes sure the old pod is gone before the new one starts.

  • Deployment
  • Secret
  • Service

Expose it with your usual Ingress or Gateway and TLS setup.

Avoiding a privileged container

privileged: true is the simplest way to get FUSE into a pod. If your cluster runs a device plugin that exposes /dev/fuse, request the device as a resource instead, and add only the SYS_ADMIN capability.

Restarts. When the S3 mount monitor finds a broken mount, the container exits with status 1, and the kubelet starts a fresh container that mounts the bucket again. No liveness probe is needed for this.

Backups. The scheduled backup worker works the same way. With a pod that always runs, backups happen on schedule.

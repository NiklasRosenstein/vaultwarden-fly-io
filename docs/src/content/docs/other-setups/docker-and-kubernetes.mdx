The image also runs outside Fly.io, with any S3-compatible bucket (AWS S3, Cloudflare R2, MinIO, Tigris and others).

## Requirements

- **FUSE access.** The container mounts the bucket as a folder. It needs the `/dev/fuse` device and the `SYS_ADMIN`
  capability. Some hosts also need AppArmor turned off for the container.
- **Only one container.** Never run two containers on the same bucket, not even for a moment during an update.
- **No volume.** All data is in the bucket.
- **Set `VAULTWARDEN_DOMAIN`.** Outside Fly.io there is no default.

All other [settings](../../reference/settings/) work the same. Vaultwarden listens on port `8080`.

## Docker

```sh
docker run -d --name vaultwarden \
  --device /dev/fuse \
  --cap-add SYS_ADMIN \
  --security-opt apparmor=unconfined \
  --restart on-failure \
  -p 8080:8080 \
  --env-file vaultwarden.env \
  ghcr.io/niklasrosenstein/vaultwarden-fly-io:<version>
```

```sh title="vaultwarden.env"
AWS_ACCESS_KEY_ID=...
AWS_SECRET_ACCESS_KEY=...
AWS_REGION=auto
AWS_ENDPOINT_URL_S3=https://s3.example.com
BUCKET_NAME=vaultwarden
AGE_SECRET_KEY=AGE-SECRET-KEY-1...
VAULTWARDEN_DOMAIN=https://vault.example.com
VAULTWARDEN_ADMIN_TOKEN=$argon2id$...
```

`VAULTWARDEN_RSA_PRIVATE_KEY` spans several lines, which an env file can't hold. Pass it with
`-e VAULTWARDEN_RSA_PRIVATE_KEY="$(cat rsa_key.pem)"`.

Put a reverse proxy with HTTPS in front of port `8080`. Set `VAULTWARDEN_IP_HEADER` to the header your proxy sets,
for example `X-Forwarded-For`.

## Kubernetes

Use one replica and the `Recreate` strategy. This stops the old pod before the new one starts. Add a `Service` and
`Ingress` as usual.

<Tabs>
<TabItem label="Deployment">

```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: vaultwarden
spec:
  replicas: 1
  strategy:
    type: Recreate # never run two writers at once
  selector:
    matchLabels: { app: vaultwarden }
  template:
    metadata:
      labels: { app: vaultwarden }
    spec:
      # Give Litestream time to upload its last changes on shutdown.
      terminationGracePeriodSeconds: 90
      containers:
        - name: vaultwarden
          image: ghcr.io/niklasrosenstein/vaultwarden-fly-io:<version>
          ports:
            - containerPort: 8080
          envFrom:
            - secretRef: { name: vaultwarden }
          env:
            - name: VAULTWARDEN_DOMAIN
              value: https://vault.example.com
          securityContext:
            privileged: true # for /dev/fuse, see the note below
          readinessProbe:
            httpGet: { path: /alive, port: 8080 }
            periodSeconds: 10
```

</TabItem>

<Aside title="Without a privileged container">
If your cluster has a device plugin for `/dev/fuse`, request the device instead and add only the `SYS_ADMIN`
capability.
</Aside>

If the bucket mount breaks, the container exits and Kubernetes starts a new one. You don't need a liveness probe for
this. See [S3 mount monitor](../../reference/how-it-works/#s3-mount-monitor).

## Why this setup?

<CardGrid>
	<Card title="Cheap to run" icon="star">
		The smallest `shared-cpu-1x` VM costs about 2 USD a month, and Fly.io stops it when nobody uses it. On a personal
		account, Fly.io has so far waived invoices under 5 USD. Storage and requests usually fit Tigris's free tier.
	</Card>
	<Card title="No volumes" icon="seti:db">
		The SQLite database is restored from S3 on boot and continuously replicated back with
		[Litestream](https://litestream.io/), encrypted with [age](https://github.com/FiloSottile/age).
	</Card>
	<Card title="Attachments in S3" icon="document">
		Attachments, Sends and the icon cache live in the same bucket, mounted with
		[GeeseFS](https://github.com/yandex-cloud/geesefs).
	</Card>
	<Card title="Configuration as code" icon="setting">
		Vaultwarden's `config.json` is built from environment variables on every start. Your `fly.toml` holds the
		whole configuration.
	</Card>
	<Card title="Self-healing storage" icon="approve-check">
		A monitor watches the S3 mount and restarts the machine when the mount breaks. It holds off while the S3
		provider itself is down.
	</Card>
	<Card title="Scheduled backups" icon="laptop">
		An optional worker writes age-encrypted, self-contained archives of your vault to a separate bucket on a
		schedule.
	</Card>
</CardGrid>

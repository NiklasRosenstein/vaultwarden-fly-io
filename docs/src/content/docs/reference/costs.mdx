You pay for the **machine** and the **bucket**. Both are on the same Fly.io bill. For a personal vault, both are
small. Most of the bucket cost comes from requests, not storage.

<CostCalculator />

:::note
Prices are from [Fly.io](https://fly.io/pricing/) and [Tigris](https://www.tigrisdata.com/pricing/), October 2026.
So far, Fly.io doesn't charge bills under 5 USD on personal accounts. This is
[not a promise](https://community.fly.io/t/does-fly-io-still-waive-5-invoices/25651).
:::

## Bucket requests

| Item | Price | Free each month |
| --- | --- | --- |
| Storage | 0.02 USD per GB-month | 5 GB |
| Class A requests (PUT, COPY, POST, LIST) | 0.005 USD per 1,000 | 10,000 |
| Class B requests (GET, HEAD and others) | 0.0005 USD per 1,000 | 100,000 |
| DELETE requests, egress | free | |

Uploads and listings (Class A) cost the most. For a machine that runs all month with default settings:

| Source | Class A per month |
| --- | --- |
| S3 mount monitor, write check (one PUT every 30 s) | 86,400 |
| S3 mount monitor, listing (when GeeseFS's cache can't answer) | up to 86,400 |
| Litestream sync (one PUT per interval, only after writes) | typically < 10,000 |
| Litestream retention checks and daily snapshot | ~2,000 |

To save requests, set `GEESEFS_MONITOR_WRITE_CHECK=false` or raise `GEESEFS_MONITOR_INTERVAL`.

## Litestream sync interval

Changes are uploaded every **10 seconds** (Litestream's own default is 1 second). If nothing changed, nothing is
uploaded. So this setting only limits the worst case:

| `LITESTREAM_SYNC_INTERVAL` | Max PUTs per month | Max cost |
| --- | --- | --- |
| `1s` (Litestream default) | 2,592,000 | ~13 USD |
| `10s` (this image) | 259,200 | ~1.30 USD |
| `60s` | 43,200 | ~0.22 USD |

## Typical totals

| Scenario | Class A per month | Tigris cost |
| --- | --- | --- |
| Always on, defaults | ~90,000 to ~185,000 | ~0.40 to ~0.90 USD |
| Always on, write check off | ~2,000 to ~100,000 | 0 to ~0.45 USD |
| Auto-stopped, ~2 hours a day | ~8,000 to ~15,000 | 0 to ~0.03 USD |

[Backups](../../keep-your-data-safe/turn-on-backups/) add a few thousand requests a month. Their storage grows with each archive, so set
an expiry rule on the backup bucket.

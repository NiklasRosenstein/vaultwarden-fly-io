Recovery

You need two things that must be available without the application or its secrets manager: the recovery private key (recovery-key.txt) and access to the backup destination.

  1. Pick an archive. Choose a completion manifest under <prefix>/completed/, download the archive it references, and check its size and SHA-256 against the manifest.

  2. Decrypt and extract into a private directory:

  3. Inspect the contents.

    • Directoryrecovered/vaultwarden/
      • db.sqlite3 standalone database
      • manifest.json capture metadata, SHA-256/size inventory, missing_files
      • Directoryfiles/
        • Directoryattachments/
          • …
        • Directorysends/
          • …
      • Directoryrecovery/
        • environment.json image inputs, incl. storage credentials, age identity, domain and RSA key
        • config.json captured admin configuration
        • rsa_key.pem signing key

  4. Validate the SQLite database and the file inventory. For a degraded archive, look at missing_files. Those files aren’t in this archive, although their database records are. Recover them from another archive or source if you can.

  5. Restore, following the migration guide:

    • Upload db.sqlite3 as import-db.sqlite and deploy once with IMPORT_DATABASE=import-db.sqlite. A standard Vaultwarden deployment can also use the file directly.
    • Upload files/attachments/ and files/sends/ under data/ in a fresh bucket.
    • Use the Vaultwarden version recorded in the manifest first, and keep the same domain and signing key.
    • Update the storage credentials and endpoints for the new bucket. The captured source credentials may have expired or been revoked.
    • Settings in recovery/config.json that were changed in the admin panel must be set again as environment options. The image regenerates config.json on every start.

  6. Verify in isolation. Log in and download an attachment before you switch traffic over or turn scheduled backups back on. Keep the original writer fenced off, and test recoveries in a separate bucket.

Note

The archive contains the application’s recovery secrets. It is not an OpenBao snapshot. Backup destination credentials, backup settings and one-time import/idle flags are deliberately left out.
